# WSL Cleanup (`wsl-cleanup.sh`)

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](https://opensource.org/licenses/MIT)
[![Platform](https://img.shields.io/badge/Platform-WSL2%20%7C%20Ubuntu-orange.svg)](https://learn.microsoft.com/en-us/windows/wsl/)
[![Shell](https://img.shields.io/badge/Shell-Bash-green.svg)](https://www.gnu.org/software/bash/)

Безопасная, идемпотентная утилита освобождения места на диске, понимающая версии — написана специально для окружений разработки в WSL2 (Windows Subsystem for Linux).

---

## Проблема

1. **Виртуальный диск только растёт.** WSL2 хранит файловую систему в динамическом виртуальном диске (`ext4.vhdx`). Файлы внутри Linux удалить можно, но Windows никогда не сжимает контейнер `.vhdx` сам по себе.
2. **Инструменты разработчика распухают.** Современная рабочая машина накапливает десятки гигабайт избыточных данных:
   - Редакторы (Cursor Server, Zed, VS Code) при каждом обновлении оставляют старые версии расширений и серверных бинарников рядом с новыми.
   - Go тянет тулчейн на ~240 МБ на каждое изменение директивы в модуле.
   - Пакетные менеджеры (`npm`, `npx`, `cargo`, `gradle`, `playwright`) кэшируют огромные архивы, распакованные бинарники и артефакты преобразования зависимостей.
   - Глобальные npm-пакеты нередко привозят бинарники под чужие архитектуры (например, `musl`-сборки или Windows `.exe` на Linux).
   - Сборка под `sudo` создаёт второй домашний каталог (`/root`) со своими собственными, никем не чищенными кэшами.

## Возможности

- 🛡️ **Безопасность по умолчанию (сухой прогон).** Без явного `--force` скрипт работает в режиме предпросмотра: показывает точные пути и размеры, но ничего не удаляет.
- 🔄 **Строгая дедупликация версий («оставить только новейшее»)**:
  - **Расширения Cursor Server.** Группируются по имени пакета: остаётся строго последняя версия, старые дубликаты и кэшированные архивы `.vsix` удаляются.
  - **Тулчейны Go.** Сохраняется новейший (он собирает и старые модули с полной обратной совместимостью), вытесненные версии удаляются.
  - **Серверы редакторов и рантаймы.** Остаются только активные и самые свежие бинарники Cursor и Zed.
  - **Node и Android Build Tools.** Остаётся последняя установленная версия, при этом уважаются пины проектов (например, `.nvmrc`).
- 🧠 **Полная защита сессий и памяти ИИ-агентов.**
  - История переписки, транскрипты, контекст и постоянная память ассистентов не трогаются никогда:
    - Claude (`~/.claude/projects`, `~/.claude/sessions`, `~/.claude/tasks`)
    - Codex (`~/.codex/sessions`, `~/.codex/memories`, `~/.codex/rules`, `~/.codex/logs_2.sqlite`)
    - Gemini / Antigravity (`~/.gemini/antigravity-acp/conversations`, `~/.gemini/antigravity-acp/brain`, сессии CLI)
    - OpenCode (`~/.local/share/opencode`)
    - GitHub Copilot CLI (`~/.copilot`: сессии, транскрипты, контекст, память, логи и конфигурация)
  - Удаляются только временные сборочные и плагинные кэши (`.tmp`, кэши плагинов), где никакой истории разговоров нет.
  - Zed при каждом запуске оставляет в `~/.cache/zed` сокет обработчика падений и никогда их не убирает: протухшие удаляются, сокеты работающих редакторов остаются.
  - `~/.cache/copilot` — это **не** состояние агента, и он **чистится**. Copilot CLI поставляется одним самораспаковывающимся бинарником и при первом запуске выкладывает туда полезную нагрузку на ~140&nbsp;МБ, рядом с двумя JSON-файлами, в первой строке которых написано *«Disposable cache … safe to delete»*, и папкой закэшированных схем MCP-инструментов. Следующий запуск распаковывает всё заново из установленного бинарника за ~2&nbsp;с и без сети — поэтому каталог освобождается в **обычном** прогоне, а не под `--deep`. Версия, помеченная живым процессом через `inuse.<pid>.lock`, остаётся до его завершения.
- 📚 **Исходный код и документация в безопасности.**
  - Деревья исходников в `~/Development`, Git-репозитории (`.git`), история коммитов и ветки не трогаются никогда.
  - Документация (`docs/`, `*.md`, офлайн-документация Rust) строго сохраняется.
  - Чувствительные конфигурации (`.env`, `local.properties`, ключи SSH/GPG, хранилища подписи Android, кластеры БД) исключены.
- ⚡ **Защита от удаления работающего.**
  - Скрипт смотрит активные процессы через `/proc/*/exe` и `/proc/*/cwd`, чтобы не снести редактор, фоновый сервер или языковой сервер, который прямо сейчас запущен.
- 🌐 **Учёт DKMS и VPN-модулей.**
  - Перед тем как трогать заголовки ядра, проверяет установленные модули DKMS (например, AmneziaWG VPN).
- 🔍 **Автоопределение пути к VHDX на стороне Windows.**
  - Через WSL Interop запрашивает реестр Windows и находит точный путь к вашему `ext4.vhdx` (даже если он перенесён на другой диск), после чего печатает готовые команды для сжатия.

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone https://github.com/coinman-dev/wsl-cleanup.git
cd wsl-cleanup
chmod +x wsl-cleanup.sh
```

### 2. Посмотреть, что будет освобождено (сухой прогон)

```bash
./wsl-cleanup.sh
```

*(В режиме сухого прогона ни один файл не удаляется.)*

### 3. Запустить очистку

#### Обычная очистка (пересобираемые кэши, старые расширения, дублирующиеся тулчейны)
```bash
./wsl-cleanup.sh --force
```

#### Глубокая очистка (плюс кэши пакетов, npx, Playwright, преобразования Gradle)
```bash
./wsl-cleanup.sh --force --deep
```

#### Полная системная очистка (всё выше + кэш APT, журнал systemd, кэши root, устаревшие бэкапы)
```bash
sudo ./wsl-cleanup.sh --force --all
```

## Параметры командной строки

| Флаг | Описание |
| :--- | :--- |
| *(по умолчанию)* | **Сухой прогон.** Считает и показывает потенциальную экономию, ничего не удаляя. |
| `--force` | Выполнить удаление по-настоящему. |
| `--deep` | Удаляет кэши пакетов, которые придётся качать заново (`~/.npm/_npx`, кэш модулей Go, крейты Cargo, браузеры Playwright, преобразования Gradle и `node_modules` в `~/Development`). |
| `--system` | Чистит системные архивы APT, сироты, списки пакетов, ограничивает журнал `systemd`, убирает ротированные логи в `/var/log`, прореживает кэши `/root` и удаляет несовместимые архитектурные заглушки глобального npm. *(Нужен sudo)* |
| `--purge-bak` | Удаляет копии для отката (`*.bak*`) в `/opt/ownlocator` и устаревшие медиа-бэкапы в `/var/lib/ownlocator/media-wsl-backup`. |
| `--purge-pgtest` | Удаляет локальный тестовый кластер PostgreSQL в `~/.local/pgtest` (если процесс postgres не запущен). |
| `--all` | Включает `--deep`, `--system` и `--purge-bak` вместе. |
| `--list-installed [слово]` | Инвентарь установленных **программ**, крупные сверху. Необязательное слово фильтрует список. |
| `--uninstall <идентификатор>` | Удаляет одну запись из этого инвентаря силами того, кто её ставил. Сухой прогон, пока нет `--force`. |
| `-h`, `--help` | Показывает справку и завершается. |

## Установленные программы

Чистка кэшей никогда не трогает программы целиком, а на машине разработчика именно они обычно составляют большую половину занятого диска. Для них есть два режима.

```bash
./wsl-cleanup.sh --list-installed
```

```
==> Installed programs — largest first
      1.9GB  agent:antigravity-acp        1.1.1     zed external agent
      818MB  sdk:emulator                 -         android sdk
      456MB  nvm:v22.22.1                 v22.22.1  nvm
      375MB  npm:@anthropic-ai/claude-code 2.1.245  /usr/local/lib/node_modules
       44MB  apt:gh                       2.45.0    apt
       16MB  go:staticcheck               -         go install
       12MB  cargo:cargo-xwin             v0.21.4   cargo install
```

Читаются apt, все глобальные корни npm, `cargo install`, `go install`, nvm, Android SDK и реестр агентов Zed. Каждая строка начинается с **идентификатора** вида `менеджер:имя` — именно он снимает неоднозначность во втором режиме: `gopls` одинаково правдоподобно и бинарник из `go install`, и языковой сервер Zed.

```bash
./wsl-cleanup.sh --uninstall gh                    # сухой прогон: показывает команду
./wsl-cleanup.sh --force --uninstall sdk:emulator  # действительно удаляет
```

Удаление отдаётся тому, кто программу ставил: apt делает `purge`, npm, cargo и `sdkmanager` — `uninstall`, а каталог, которым не владеет ни один установщик, уходит через тот же `drop()`, что и всё остальное, что удаляет скрипт. Короткое имя работает, когда оно есть только у одного менеджера; иначе скрипт печатает кандидатов и останавливается.

Три намеренных ограничения:

- **Из apt показываются только вручную установленные пакеты.** Зависимость, которую никто не выбирал, — не программа, которую кто-то установил, а сирот среди них и так убирает `--system`. На попытку удалить такую скрипт прямо об этом говорит, а не делает вид, что пакета нет.
- **Пакеты apt с приоритетом Essential и required отклоняются.** По запросу apt утащит вместе с `libc6` полсистемы; здесь ответ — нет.
- **Сначала всегда сухой прогон.** Для apt предпросмотр включает полный каскад (`apt-get -s purge`), так что видно, что пакет тянет за собой, ещё до `--force`.

## Сжатие виртуального диска (`.vhdx`) в Windows

После удаления файлов внутри WSL2 освободившееся место остаётся занятым внутри контейнера виртуального диска. Чтобы сжать сам файл `.vhdx` на хосте Windows:

`wsl-cleanup.sh` печатает точный найденный путь в конце прогона.

### Вариант A: PowerShell (Windows Pro / Enterprise с Hyper-V)

Выполнить в **PowerShell от администратора**:

```powershell
wsl --shutdown
Optimize-VHD -Path "<путь-из-вывода-скрипта>\ext4.vhdx" -Mode Full
```

### Вариант B: Diskpart (Windows Home / Standard)

Выполнить в **командной строке или PowerShell от администратора**:

```cmd
wsl --shutdown
diskpart
```

Внутри `diskpart`:

```text
select vdisk file="<путь-из-вывода-скрипта>\ext4.vhdx"
attach vdisk readonly
compact vdisk
detach vdisk
exit
```

## Настройка

Поведение меняется переменными окружения:

```bash
DEV_DIR=~/Development     # Корневой каталог ваших репозиториев (по умолчанию: ~/Development)
JOURNAL_KEEP=200M         # Целевой размер журнала systemd после урезания (по умолчанию: 200M)
TMP_AGE_DAYS=7            # Порог возраста для очистки /tmp (по умолчанию: 7 дней)
```

Пример:
```bash
DEV_DIR=/path/to/my/projects ./wsl-cleanup.sh --force
```

## Что чистится, а что сохраняется

| Категория | Чистится / освобождается | Сохраняется / защищено |
| :--- | :--- | :--- |
| **ИИ-агенты** | Временные файлы (`.tmp`, кэш плагинов), самораспакованная нагрузка Copilot CLI (`~/.cache/copilot`, ~140 МБ, восстанавливается офлайн за ~2 с) | **Все** сессии, история переписки, память, правила, задачи (`~/.claude`, `~/.codex`, `~/.gemini`, `~/.copilot`, `~/.local/share/opencode`) |
| **Cursor и редакторы** | Старые версии расширений, кэшированные архивы VSIX, вытесненные серверные бинарники | Последние версии расширений, активные серверные бинарники, настройки |
| **Go** | Старые версии тулчейнов (`toolchain@...`) и кэш модулей `golang.org/x` под `--deep` | **Новейший** тулчейн Go |
| **Node / NPM** | `~/.npm/_npx`, `_cacache` | Активная версия NVM, версии, закреплённые в `.nvmrc` |
| **Бинарники чужих платформ** | Пакеты, помеченные под ОС или архитектуру, которую эта машина не может исполнить — `win32-*`, `darwin-*`, `*-arm64` — где бы их ни поставили npm или prebuildify | Всё непомеченное, а также musl-сборка без соседней glibc (Codex поставляет **только** статический musl-бинарник, и на glibc он прекрасно работает) |
| **Rust / Cargo** | Перекачиваемый индекс и кэш реестра (под `--deep`), сборочный вывод `target/` | Офлайн-документация (`rust-docs`), активные тулчейны |
| **Android / Gradle** | Вытесненные build-tools, сборочный кэш, преобразования (под `--deep`) | Активные build-tools, дистрибутив wrapper, хранилища ключей |
| **Репозитории** | Артефакты сборки (`target/`, `build/`, `dist/`, `.gradle/`, `reports/`) | Весь исходный код, история Git, документация, конфиги `.env` |
